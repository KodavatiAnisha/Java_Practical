Internally how Javac works


When you run javac, it is the Java compiler that converts your .java file into .class file (bytecode). Internally it works in steps.

How javac Works Internally
1. Reading Source Code
javac reads the .java file
Converts characters into tokens

Example:

int a = 10;

Becomes tokens like:

int
a
=
10
;

This step is called Lexical Analysis.

2. Syntax Analysis (Parsing)
Checks grammar rules of Java
Builds a tree structure called AST (Abstract Syntax Tree)

Example check:

Missing semicolon
Wrong brackets
Incorrect syntax

If error → compilation stops here.

3. Semantic Analysis
Checks meaning of code
Type checking happens here

Example:

int a = "hello";  // error

It ensures:

Correct data types
Variables declared before use
Method correctness
4. Symbol Table Creation
Stores information about:
Variables
Methods
Classes

Example:

a → int
main() → method
5. Bytecode Generation
Converts AST into .class file
This file contains Java Bytecode

Example:

MyClass.java → MyClass.class

This bytecode is not machine code, it runs on JVM.

6. Optimization (Optional step)
Removes unused code
Improves performance slightly
After javac

The output .class file is executed by:

👉 Java Virtual Machine (JVM)

javac → bytecode
java → runs bytecode
Simple Flow
.java file
   ↓
Lexical Analysis
   ↓
Syntax Analysis
   ↓
Semantic Analysis
   ↓
Bytecode Generation
   ↓
.class file
